## 3. 로컬 저장과 실패 계약

| 데이터 | 저장 필드와 기본값 | 쓰기·조회 조건 |
| --- | --- | --- |
| 공통 | 클라이언트 UUID v7 `id`. `createdAt`·`updatedAt`·`deletedAt`은 UTC epoch ms 정수이며 활성 행의 `deletedAt=null`. | 활성 조회는 삭제 행을 제외한다. 키와 소유 연결은 현 로컬 데이터 집합 안에서 검증한다. 파일은 blob을 가리키는 안정된 로컬 식별자를 저장한다. |

| CollageState | §6.4 제품 배치 계약은 WP-4. | 아이템을 이동한 후 원래 노트에는 표시하지 않고 대상 노트에서 미배치 상태로 취급한다. 실제 placement 전환의 담당 범위는 D-02와 WP-4에서 확정한다. |

| 실패 | 관찰 가능한 결과 |
| --- | --- |
| IndexedDB 초기화/쓰기 실패·용량 초과 | 화면에서 실패와 재시도 가능 여부를 알린다. 성공 행·성공 토스트를 표시하거나 기존 DB를 초기화하지 않는다. 입력과 현재 노트 선택은 가능한 범위에서 유지한다. |
| 파일 제한·형식 검증 | MIME 접두사로 image/video/audio 분류. 이미지 20MB·음악 50MB·영상 200MB 초과와 기타 MIME은 저장을 거부하고 파일별 이유를 알려준다. 저장 가능한 드롭 파일은 각각 한 아이템으로 처리하며 완료된 파일을 재시도에서 중복 저장하지 않는다. |
| URL·클립보드 | URL 단독은 http/https 및 도메인 표로 분류하고 문장 속 URL은 text로 둔다. 포커스 시 클립보드 거부는 조용히 생략하고 동일 URL을 반복 제안하지 않는다. 입력 편집 중 붙여넣기는 에디터의 기본 삽입을 우선한다. 화면 바깥 붙여넣기는 CAP-06 캡처로 진행한다. |
| 경합·파일 지연 | 에디터는 아이템 ID와 draft revision별로 쓰기를 직렬화한다. 500ms 타이머 또는 이탈 flush는 같은 revision을 한 번만 저장한다. A→B 전환 후 A 응답은 B draft에 적용하지 않는다. 삭제한 행은 지연 저장·썸네일 결과가 복구하지 않는다. 유저 썸네일·잠금 유형을 덮지 않는다. |
| 삭제·복구 | 메모 삭제 시 5초간 실행 취소. 해당 삭제 리비전에만 복구를 허용한다. 30일 후 영구 정리는 다음 시작/점검 시각에서도 적용되어야 하며 여전히 참조되는 파일은 보존한다. 노트 삭제, 아이템 이동, 삭제 취소가 교차하더라도 유효하지 않은 bookId를 활성 행에 남기지 않는다. |

## 4. 화면·입력 수용 기준

| 접점 | 정상·빈·오류·접근성 |
| --- | --- |
| S-01 | 표준 컴포넌트로 위쪽 책장, 아래쪽 빠른 작성·태그·메모 목록. 표지는 최근 수정순, 메모는 최신순, 제목 미지정이면 본문 첫 줄. `전체`가 첫 태그이며 사용 0회 태그는 숨긴다. 기본 노트 초기화 후 무자료 상태 안내, 선택 태그 무결과 안내, 저장 중/실패 상태를 갖는다. IME 조합 Enter는 제출하지 않고 저장 성공 시 포커스를 유지한다. |
| S-05 | 생성·편집 공용 시트. 닫으면 트리거로 포커스 복원, 포커스 이탈 방지, 오류 필드에 접근 가능한 설명. 이름 필수, 시기 설명 선택, 8종 프리셋 및 3:4 사용자 이미지. 기본 노트는 삭제 버튼을 제공하지 않는다. 다른 노트의 삭제 확인에서 기본 노트로 이동/함께 삭제를 구분한다. |
| S-02 | 새 작성과 기존 메모 모두 지원. 뒤로·노트 이동·삭제 메뉴, 날짜/요일, 제목, 본문·미디어 블록, 태그와 툴바. Markdown 굵게·기울임·글머리·번호 목록만 제공하며 원시 HTML은 실행하지 않는다. 파일 재생은 화면 이탈 시 정리하고 스트리밍 링크는 외부에서 연다. 로딩·삭제된/없는 메모·저장 실패를 구분하며 앱 이탈 뒤 마지막 확정 저장분을 복원한다. |
| 태그 | trim·영문 소문자화·최대 20자·아이템당 10개, 중복 제거. 한 글자부터 활성 메모 기준 빈도순 5개. 추가/삭제는 메모 저장의 선행 조건이 아니다. 필터 갱신 ≤100ms, 태그 탭 상태가 책장 데이터와 분리된다. |
| 절차 썸네일 | 같은 내용 해시와 유형에서 색·패턴이 결정적이며 즉시 표시, 생성 목표 ≤50ms. 저장하는 원본은 긴 변 512px WebP이며 테두리·프레임·스킨을 포함하지 않는다. 생성형·서버 링크 메타는 후속 범위. 일시적 디코딩 실패에도 최초 절차 썸네일을 유지한다. |
| PWA | 매니페스트·서비스 워커를 실제 웹 export에서 검증한다. 온라인 선행 방문 후 오프라인으로 S-01·S-02·S-05를 다시 연다. 설치 가능한 대상 환경에서 Web Share Target URL·텍스트를 1회만 저장하고 성공 여부를 표시한다. 브라우저 미지원 시 다른 캡처 진입은 동작한다. |

새 화면은 `320/390/768/1150/1280` 폭과 필요한 다크/모션 상태에서 확인한다. 배치 약속은 책장·메모 영역, 목록 행의 썸네일·텍스트, 에디터 헤더·툴바, 시트 필드·버튼에 건다. G0~G8, 44px 터치, 4.5:1 대비, 키보드·스크린 리더 접근성을 확인한다. 레거시 경로와 `/collage-preview`에서도 기본 진입을 유지한다.

## 5. 검증 계획

| ID | 증거 |
| --- | --- |
| W2-01 | 격리 브라우저의 저장소 초기화·새로고침·동시 초기화에서 기본 노트 한 권. 노트 생성과 빠른 입력, 삭제 두 선택, 쓰기 실패에서 원자성과 입력 보존을 검사한다. |
| W2-02 | MIME 3종 및 경계 파일, 지원 도메인 표 전체·유사 도메인·문장 속 URL, paste/drop/IME/클립보드 거부·중복을 검증한다. 다섯 유형의 썸네일이 네트워크 없이 즉시 있고 동일 내용에서 결과가 결정적인지 검사한다. |
| W2-03 | 가짜 시계와 지연 쓰기로 499/500ms 경계, 이탈 flush, A→B 이동 후 A 완료, 삭제→지연 썸네일, 5초 undo/30일 정리, 실패 뒤 재시도를 검증한다. 화면 값과 재시작 후 저장 내용을 둘 다 단언한다. |
| W2-04 | 실제 export에서 노트 생성 → 오프라인 저장 → 태그 필터 → 편집·노트 이동 → 새로고침 후 보존. 기존 레거시 저장 자료와 새 제품 흐름의 공존 및 PWA offline/share 진입을 별도 컨텍스트에서 확인한다. |
| W2-05 | NFR-01의 앱 열기→저장 ≤3초, 웹 재방문→입력 가능 ≤1.5초 및 Enter→상단 행 ≤200ms. NFR-02 초기 JS gzip ≤500,000B, Skia·CanvasKit·matter.js 미포함. 브라우저·캐시·네트워크와 측정 경계를 기록한다. |
| W2-06 | 실제 화면에서 배치 약속·실패 표시·키보드 탐색 확인. 구현 전 실패와 구현 후 통과를 기록하고 스크린샷을 점검한다. Playwright 건수와 CI 검사 범위를 분리한다. |

구현이 승인되면 `app/`에서 `npm run typecheck`, `npm run lint`, `npm test`, `npm run export:web` 및 신규/기존 Playwright 결과를 기록한다. 공개 API·서버 동기화·실제 사용자 DB·운영 배포 검증은 후속 작업이다.
