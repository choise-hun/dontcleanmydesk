1. 캔버스 컨테이너의 CSS px 크기를 실제 DOM에서 측정한다. 기준 조각 한 변은 `s = clamp(min(W,H) * 0.22, 96, 220)`, 목표 수는 `N = clamp(floor(W*H*0.35/(s*s)), 8, 15)`, 제품용 계산 결과는 `visible = min(N, itemCount)`. 예시 결과 390×844 → 12, 768×1024 → 9, 1440×900 → 11. 화면 기본 fixture는 D2 적용.
2. 양면 노트의 중심은 뷰포트 중앙. Step 1 시안용 기본 비율은 폭 `min(W*0.86,H*1.05)`, 높이 `min(H*0.67,W*1.04)`. 최종 값은 시안 결정을 반영한다. 노트 폭을 1로 두고 x·y 모두 그 폭으로 나눈다. 렌더링/히트 테스트는 노트 중심·폭으로 역변환한다.
3. 고정 시드로 기본 10개 중 7개의 중심을 속지 내부에, 3개를 노트 경계에 둔다. 경계 조각은 바깥 변을 걸치고 세 조각 모두 바깥으로 드러난 부분이 있어야 한다. 다른 fixture는 `round(count*0.30)`개를 경계에 둔다. 각도는 ±12° 균등, 배율은 0.85~1.15. 최소 두 조각이 서로 겹친다.
4. 모든 조각의 가려진 면적은 상위 z 회전 사각형들의 합집합과 해당 조각 면적의 교차로 계산한다. 그림자와 오브제는 배치 가려짐 계산에서 제외하고 시안·스크린샷에서 읽힘을 확인한다. 70% 초과 또는 필요한 겹침이 없는 후보는 최대 10회 다시 뽑는다. 소진되면 해당 크기대의 결정적 검증용 안전 배치를 사용하고, 동일 조건을 다시 검증한다. 안전 배치도 실패하는 크기는 오류 상태에서 처리하고 수용 폭에서 이 경로가 발생하면 실패다.
5. WASM 준비 → Scene 평가 → 양수 치수에서 첫 장면 표시. 각 비동기 작업은 현재 세대만 결과를 반영한다. 살아 있지 않은 세대가 만든 리소스는 정리하고 라우트 이탈 시 구독·RAF를 해제한다. 폰트나 합성 그림 생성이 비동기라면 똑같이 적용한다. 카드 글자는 필요하면 브라우저 시스템 글꼴로 임시 이미지에 그려 Skia에 올린다. DOM에 두 번째 장면 canvas를 붙이거나 외부 폰트·이미지를 요청하지 않는다.

## 4. WP-1-2 — 물리와 입력

| 항목 | 임시 계약 |
| --- | --- |
| 바디 | 회전 사각형. 표시 치수와 초기 배율을 사용하고 들어올리기 연출 배율은 시각에만 적용. 중력 0, `frictionAir=0.12`, `restitution=0.05`. |
| 상태·마스크 | `resting → held → thrown → resting`. 맞은 대상은 `resting → pushed → resting`. `held/thrown` 질량 1, `resting/pushed` 질량 3. Matter category/mask는 상호 허용된 driver↔target 및 각 조각↔wall만 허용한다. 정지·밀린 대상끼리는 겹칠 수 있다. 새 유효 드래그 시 이전 `thrown`이 있으면 `pushed`로 넘겨 driver는 최대 1개다. |
| 시작·이동 | 포인터 다운 때 회전·배율 반영 히트 중 최상단을 예약하고 하나의 pointer ID만 캡처한다. 원래 포인터와 조각 중심 사이 차이를 유지. 이동이 8 CSS px에 도달하면 드래그로 확정해 z를 최대+1, lift를 1로 한다. 미확정 탭은 배치·z·속도를 변경하지 않는다. 배경·보조 포인터는 무시한다. |
| 던지기 | 최근 80ms의 실제 포인터 샘플과 이벤트 시간 차로 마지막 속도를 산출하고, 60Hz 기준 최대 24 CSS px/frame으로 제한한다. 유효 샘플이 둘 미만이거나 마지막 이동이 80ms 이상 지난 경우 초기 속도 0. 드래그 중 접근은 프레임 내 분할해서 충돌을 건너뛰지 않도록 한다. 놓으면 lift를 0으로 내려 시각상 원래 크기·그림자로 복귀한다. |
| 정지·경계 | 호출자 시계의 고정 tick `1000/60`ms. 속도 크기 <0.05 CSS px/frame이 연속 10 tick일 때 선속도·각속도를 0으로 하고 정지. 정지 대상과 접촉 상태에서는 밀림 처리가 끝날 때까지 정지 카운터가 새 접촉/속도 초과에서 초기화된다. 15% 바깥 벽을 두고 각 substep에서 중심을 [0,W]×[0,H]로 제한해 밖 방향 속도만 제거한다. |
| 취소·수명 | `pointercancel`, 예기치 않은 캡처 해제, 창 블러, 치수 변경에서 진행 중 입력을 닫고 던지기 없이 마지막 유효 위치에 둔다. 정상 release와 뒤따르는 lost capture는 한 번만 정리한다. 0크기에서는 정지. 다른 양수 치수로 바뀌면 현재 위치를 노트 좌표로 변환한 스냅샷에서 바디를 재생성하고 새 경계로 제한한다. 조각 ID·z·회전과 배율을 유지한다. |
| 메모리 상태 | 캔버스 포인터 좌표는 현재 입력 영역의 bounding rect 기준 CSS px로 변환한다. 화면 DPR은 렌더링에만 관여한다. 완료 위치와 밀려난 조각 위치는 메모리 pose에 기록한다. 언마운트·숨은 탭에서 tick/입력을 종료하고 stale RAF를 폐기한다. 새 탭/새 진입은 같은 seed fixture에서 다시 시작한다. |

- 포인터 캡처/터치 스크롤 억제는 상호작용 영역만 사용한다. 줄인 동작에서도 직접 끌기와 충돌은 체험하되 자동 잎 움직임·놓은 뒤 관성·lift 전환 애니메이션을 줄인다. 취소와 reduced-motion 관성 생략은 의도적인 속도 0 경로다. 일시적인 0크기나 숨은 탭에서는 마지막 유효 스냅샷을 보관하고, 다시 보일 때 같은 배치에서 속도 0으로 시작한다.
- Matter의 RAF 독립성을 유지한다. 활성화 시각과 dt는 외부에서 공급하고, 시작·페인트·bake의 참조를 매 tick 교체하지 않는다. 장시간 백그라운드 이후 누적 dt를 한꺼번에 실행하지 않는다. 반복 진입/취소에도 살아 있는 엔진과 루프를 하나씩만 둔다.

## 6. 구현 제약

- 기존 홈·`/desk`·네이티브 조작·스토어·스키마·API·공용 테마 export를 보존한다. 신규 라우트는 목업 전용이며 실제 `Item`·`RoomState`를 생성하거나 사용자 데이터에 쓰지 않는다.
- 목업 이미지를 실제 사용자 에셋으로 저장하지 않는다. 번들 분리를 위해 무거운 모듈을 홈이나 루트 레이아웃에서 import하지 않는다. 기본 설정은 Expo SDK 58 [비동기 라우트](https://docs.expo.dev/router/web/async-routes/)와 [플랫폼 파일 규칙](https://docs.expo.dev/router/advanced/platform-specific-modules/)을 따른다.
- 설계 근거는 이 표의 코드와 Expo SDK 58 기준을 사용한다. 구현에서 추가 파일·제품 계약 변경이 필요하면 해당 근거와 영향을 먼저 제시한다. 하네스 H-ARCH-05·07·09, H-DOC-03을 적용하고 스킵·단언 약화·픽셀 골든 테스트로 성공을 대신하지 않는다.
