## 3. WP-2 Step 분할

Step은 4개(상한)이고 모두 시니어 직접 구현이다. 3개로 합치면 앞의 두 Step이 크기 상한(파일 7개·700줄)을 넘는다.

| Step | 내용 | 상태 |
| --- | --- | --- |
| WP-2-1 | 빠른 메모 저장: 로컬 저장소, 기본 노트 `첫 노트`, S-01 빠른 작성·메모 목록, 레거시 `/legacy` 분리 | 구현 대기(명세 완료) |
| WP-2-2 | 노트 책장과 S-05: 표지 카드, 노트 생성·편집·삭제(기본 노트로 옮기기/함께 삭제), 표지 탭 → 노트별 목록 | 명세 전 |
| WP-2-3 | 다중 입력·분류·썸네일·PWA: URL 분류, 파일·드롭·붙여넣기·클립보드, 첨부, 절차 썸네일, 서비스 워커 | 명세 전 |
| WP-2-4 | S-02 에디터·자동 저장, 태그·태그 탭, 노트 이동, 삭제 5초 실행 취소 | 명세 전 |
| 관문 | 대기능 적대적 리뷰(Codex/GPT) + 여정 E2E + NFR-01·02 계측 | 대기 |

WP-2-3·WP-2-4는 크기 상한을 넘을 수 있다. 각 명세를 쓸 때 실제 파일 목록으로 다시 재고, 넘으면 Step을 늘리지 않고 계획 수준 분리를 사용자에게 제안한다.

## 5. WP-2-1 핵심 계약 (요약. 원본은 `개발산출물/명세/WP-2-1_구현명세.md`)

- 새 파일: `app/src/data/notes.ts`(타입·순수 함수·저장소), `localDb.web.ts`(IndexedDB `collage-notes` v1: `books`·`items`·`meta`), `localDb.ts`(모바일 stub), `app/src/app/index.web.tsx`(S-01), `app/src/features/home/home.module.css`, 테스트 2개. 기존 `index.tsx`는 `legacy.tsx`로 이동하고 `_layout.tsx`는 레거시 경로에서만 `store.init()`·동기화를 시작한다.
- 쓰기는 한 트랜잭션 안에서 읽고 동기로 결정한다. 기본 노트는 동시 초기화에도 한 권만 생긴다. ID는 UUID v7.
- 저장 실패(용량 초과·삭제된 노트·IndexedDB 불가) 때는 입력을 유지하고 오류를 보여준다. 실패한 DB 열기 Promise를 캐시하지 않는다.
- 레거시 `store`·`sync`·`collect`·`desk`와 DB `messy-room`은 건드리지 않는다.
- 착수 때 확인할 것(미확인): Expo Router에서 `index.tsx`와 `index.web.tsx`가 함께 있을 때 웹이 `.web.tsx`를 고르는지, Safari 한글 IME 확정 Enter의 `isComposing`.
