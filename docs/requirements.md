# 아이디어 콜라주 노트 앱 — 요구사항 정의서

Nov 14, 2026 · @더덕

이 문서는 기획안과 UI 레퍼런스를 AI가 바로 상세 명세와 코드로 옮길 수 있도록 요구사항 ID, 수용 기준, 데이터·API 계약, 단계별 작업 단위로 재구성한 것이다. 원문에 없어 채운 값은 모두 10장에 `가정`으로 표시했다.

## 0. 이 문서를 AI에 투입하는 법

이 문서 하나가 명세 작성과 구현의 유일한 기준이다. AI는 아래 규칙을 따른다.

1. **읽는 순서**: 1장(범위) → 2장(용어) → 3장(화면) → 4장(기능) → 5\~7장(알고리즘·데이터·API) → 9장(작업 패키지). 작업은 9장의 패키지 단위로 하나씩 수행한다.
2. **ID 규칙**: 화면 `S-nn`, 기능 요구사항 `FR-영역-nn`, 비기능 `NFR-nn`, 작업 패키지 `WP-n`, 가정 `A-nn`, 미결정 `Q-nn`. 명세·코드 주석·커밋·테스트 이름에 해당 ID를 그대로 인용한다.
3. **우선순위 표기**: `P1`\~`P8`은 9장의 개발 단계 번호다. 현재 작업 중인 패키지보다 뒤 단계의 요구사항은 구현하지 않되, 데이터 모델과 인터페이스는 뒤 단계를 막지 않게 설계한다.
4. **용어 고정**: 2장의 용어와 식별자(`Item`, `Book`, `CollageState` 등)를 바꾸거나 동의어를 만들지 않는다.
5. **가정과 미결정**: `A-nn`은 그대로 구현하되 한 곳(설정 상수 파일)에서 바꿀 수 있게 둔다. `Q-nn`에 걸리는 부분은 임의로 결정하지 말고, 10장의 임시 기본값으로 구현한 뒤 결과 보고에 해당 `Q-nn`을 나열한다.
6. **금지**: 웹 전용 라이브러리(DOM 직접 조작, 웹 전용 UI 킷)를 공용 코드에 쓰지 않는다. 플랫폼 차이는 `*.web.ts` / `*.native.ts` 분기 파일 안에만 둔다. 요구사항에 없는 기능(소셜, 공유 피드, AI 자동 태깅 등)을 추가하지 않는다.
7. **완료 판정**: 각 요구사항의 수용 기준과 9장 패키지의 완료 기준을 모두 충족해야 완료다. 수용 기준은 자동 테스트 또는 수동 확인 절차로 옮긴다.

레퍼런스 이미지는 3장에서 글로 풀어 썼다. 이미지를 함께 투입할 수 있으면 `image 4.jpg`(책장·에디터), `image.jpg`(모눈 노트 콜라주), `image 1.jpg`(빈티지 스크랩북 콜라주)를 같이 넣는다. 이미지의 색·일러스트는 분위기 참고용이며 그대로 복제하지 않는다.

## 1. 제품 정의와 범위

아이디어(글·사진·음악·영상·링크)를 3초 안에 노트에 끼워 넣고, 노트를 펼치면 조각들이 콜라주로 겹쳐 나타나 우연한 마주침을 주는 앱이다. 순서대로 열람하는 메모장이 아니라 스크랩북을 펼치는 경험이 핵심이다.

| --- | --- | --- |

| PR-2 | 무엇이든 넣는다 | 글·사진·음악·영상·링크를 모두 받는다. 유형은 자동 분류, 태그는 선택. |

| PR-7 | 분위기는 테마로 | 아이템은 순수 내용만 갖고, 곉모습은 전부 테마가 렌더링 시점에 입힌다. |

### 비목표

- 협업·공유 피드·소셜 기능은 만들지 않는다. 개인용 단일 계정 앱이다.
- 자동 분류에 AI를 쓰지 않는다. MIME 타입과 URL 패턴만 쓴다.
- 3D 렌더링은 하지 않는다. 모든 연출은 2D 레이어와 2D 물리다.
- 폴더 중첩, 노트 안의 페이지 번호 관리 같은 정리 기능은 만들지 않는다.
- 생성형 이미지는 사용자가 요청할 때만 호출한다. 자동 호출은 없다.

## 2. 용어집

화면 문구는 한국어 용어를, 코드와 스키마는 식별자를 쓴다.

| 용어 | 식별자 | 정의 |
| --- | --- | --- |
| 아이템(메모) | `Item` | 저장된 아이디어 하나. 유형은 `text` / `image` / `video` / `music` / `link`. |
| 조각 | `Piece` | 콜라주 화면에 그려진 아이템의 시각적 모습. 썸네일 원본 + 테마 스킨. 저장 엔티티가 아니라 렌더링 결과다. |
| 노트(책) | `Book` | 한 시기·테마의 아이템 묶음. 표지를 가진다. |
| 책장 | `Shelf` | 노트 표지가 나열된 메인 화면 상단 영역. |
| 메모 칸 | `QuickPane` | 메인 화면 하단의 태그 탭 + 메모 목록 + 빠른 작성 영역. |
| 콜라주 | `Collage` | 노트를 펼쳤을 때 양면 페이지와 책상 가장자리에 조각이 겹쳐 놓인 화면. |
| 배치 상태 | `CollageState` | 노트별로 저장되는 조각 위치·회전·레이어 정보. 다시 열 때 복원한다. |
| 책갈피 속 | `tucked` | 아이템이 노트에 있지만 현재 콜라주에 나와 있지 않은 상태. |
| 펼치기 | `open` | 노트를 탭해 콜라주 화면으로 들어가는 동작. |
| 쏟아내기(뒤지기) | `spill` | 책갈피 속 조각을 한두 개 꺼내고 같은 수의 오래된 조각을 넣는 동작. |
| 들춰보기 | `peek` | 위 조각을 밀어 아래 조각을 드러내는 동작. |
| 자연 순환 | `rotation cycle` | 시간이 지나며 오래된 조각이 들어가고 다른 조각이 나오는 규칙. |
| 침입자 | `intruder` | 필터 중에 화면 밖에서 미끄러져 들어오는, 필터에 맞지 않는 조각 하나. |
| 스킨 | `skin` | 유형별 조각 곉모습(폴라로이드, 찢어진 메모지 등). 테마가 정의한다. |
| 오브제 | `prop` | 페이지 테두리의 장식 소품(황동 클립, 집게, 실링 스탬프, 솔방울, 말린 꽃). 상호작용 없음. |
| 테마 | `Theme` | 속지·책상·스킨·오브제·빛·물리·소리를 정의한 매니페스트(JSON) + 에셋 묶음. |
| 절차적 썸네일 | `procedural thumbnail` | 내용 해시·텍스트 발췌·파형에서 색과 패턴을 뽑아 기기에서 즉시 만드는 썸네일. |

## 3. 화면 정의 (와이어프레임 기준)

화면은 7개다. 모바일 세로 화면을 기준으로 설계하고, 웹 데스크톱에서는 S-01·S-02를 최대 폭 480px 중앙 정렬, S-03은 창 전체를 쓴다(A-01).

| ID | 화면 | 단계 | 근거 |
| --- | --- | --- | --- |
| S-01 | 홈: 책장 + 메모 칸 | P2 | `image 4.jpg` 좌측 시안 |
| S-02 | 메모 에디터(작성·상세) | P2 | `image 4.jpg` 우측 시안 |
| S-03 | 콜라주 펼치기 | P1, P4\~P6 | `image.jpg`, `image 1.jpg` |
| S-04 | 순서 보기(리스트) | P5 | 기획안 8장 |
| S-05 | 노트 생성·편집(표지 지정) | P2 | 기획안 8장 |
| S-06 | 설정(테마·계정·동기화) | P3, P6 | 기획안 9장 |
| S-07 | 로그인 | P3 | 기획안 10장 |

### S-01 홈: 책장 + 메모 칸

화면을 위아래 두 영역으로 나눈다. 위는 따뜻한 베이지 배경의 책장, 아래는 위쪽 모서리가 둥근 밝은 시트(메모 칸)다. Skia 없이 표준 컴포넌트로만 그린다.

| 요소 | 내용 | 동작 |
| --- | --- | --- |
| 헤더 | 제목 "내 노트", 우측에 `+` 버튼과 `⋮` 메뉴 | `+` → S-05(새 노트), `⋮` → S-06 |
| 표지 캐러셀 | 세로형 표지 카드를 가로 스크롤로 나열. 카드 = 표지 이미지 + 책등 쪽 세로 제목 + 아래 그림자. 정렬은 최근 수정순 | 탭 → S-03, 길게 누르기 → S-05(편집) |
| 태그 탭 | `전체` + 사용자 태그를 사용 빈도순으로 가로 스크롤. 선택된 탭은 굵은 글씨 + 아래 짧은 밑줄 | 탭 → 메모 목록 필터 |
| 빠른 작성 입력 | 메모 칸 맨 위 한 줄 입력창("아이디어를 적거나 붙여넣기") + 첨부 버튼 | Enter → 즉시 저장, 확장 아이콘 → S-02 |
| 클립보드 제안 | 클립보드에 URL이 있으면 입력창 아래에 "복사한 링크 저장" 칩 | 탭 → 링크 아이템 저장 |
| 메모 목록 | 행 = 조각 썸네일(정사각, 둥근 모서리) + 제목(없으면 본문 첫 줄) + 소속 노트 이름 + 날짜 칩. 최신순 | 탭 → S-02 |
| 드롭 영역(웹) | 파일을 창 위로 끌면 화면 전체에 점선 오버레이 | 놓으면 아이템 저장 |

상태: 노트가 0권이면 캐러셀 자리에 "첫 노트 만들기" 카드 하나. 메모가 0개면 목록 자리에 한 줄 안내와 입력창 포커스. 태그 필터 결과가 0개면 "이 태그의 메모가 없습니다".

레퍼런스와 다른 점: 레퍼런스의 하단 목록은 노트 목록("21 entries")이지만, 기획안은 메모 목록으로 정의한다. 기획안을 따른다(Q-01).

### S-02 메모 에디터

베이지 배경 위에 흰 종이 카드 한 장이 놓인 노트 페이지 형태다. 새 작성과 기존 메모 열람·편집을 같은 화면으로 처리한다.

| 요소 | 내용 | 동작 |
| --- | --- | --- |
| 헤더 | `←` 뒤로, 소속 노트 이름, `⋮` 메뉴 | 노트 이름 탭 → 노트 선택 시트, `⋮` → 썸네일 지정·삭제 |
| 날짜 줄 | 좌측 작성 날짜("2026년 11월 14일"), 우측 요일("토요일"). 아래 얇은 구분선 | 읽기 전용 |
| 제목 | 플레이스홀더 "제목" | 선택 입력 |
| 본문 | 텍스트 블록과 미디어 블록(이미지·영상·음악·링크 카드)의 세로 나열 | 텍스트 편집, 미디어 탭 → 재생·확대 |
| 태그 줄 | 본문 아래 태그 칩 목록 + `+ 태그` | 추가·제거 |
| 하단 툴바 | 왼쪽: 첨부(사진·파일), 링크 붙여넣기. 오른쪽: 서식(굵게·기울임·목록), 태그, 노트 이동 | 각 기능 실행 |

저장은 자동이다. 입력이 500ms 멈추거나 화면을 나갈 때 저장하고 저장 버튼은 두지 않는다(A-02). 레퍼런스의 펜(그리기) 아이콘과 페이지 번호는 만들지 않는다(Q-02).

### S-03 콜라주 펼치기

나무 책상 위에 펼쳐진 양면 노트가 있고, 조각들이 페이지와 책상 가장자리에 비스듬히 겹쳐 놓인다. Skia 캔버스 한 장으로 그리며 이 화면에 들어올 때 지연 로딩한다.

레이어 순서(아래→위)는 고정이다.

1. 책상 나무 텍스처와 사용감 디테일
2. 펼쳐진 양면 노트(속지 텍스처 + 가운데 접힘 그림자)
3. 조각들 + 광원 방향 그림자(따뜻한 갈색 톤, 회색 금지)
4. 테두리 오브제(황동 클립, 집게, 솔방울, 말린 꽃)
5. 나뭇잎 그림자 오버레이(`multiply`, 아주 천천히 흔들림)
6. 빛 번짐(`screen` 그라데이션) + 비네팅

조각 스킨(기본 테마):

| 유형 | 스킨 | 표시 내용 |
| --- | --- | --- |
| `image` | 폴라로이드 또는 빈티지 인화 사진 | 사진 + 흰 테두리 |
| `text` | 찢어진 메모지, 타자기 노트 조각, 엽서 | 본문 앞부분 최대 80자 |
| `music` | 앨범 커버 카드 또는 찢어진 악보 조각 | 커버 + 곡명 |
| `video` | 필름 스냅샷 인화 사진 | 프레임 + 재생 표시 |
| `link` | 찢어진 신문·잡지 스크랩 또는 우표 | OG 이미지 + 제목 + 도메인 |

제스처:

| 입력 | 동작 |
| --- | --- |
| 조각 탭 | S-02로 이동 |
| 조각 끌기 | 위치 이동. 놓는 즉시 `CollageState` 저장. 닿은 조각은 물리로 밀린다 |
| 조각 두 손가락 회전·핀치 | 회전·크기 변경(웹: 휠 = 회전, Shift+휠 = 크기) (A-03) |
| 페이지 구석 끌어당기기 | 쏟아내기. 웹·모바일 공통 |
| 기기 흔들기 | 쏟아내기. 모바일 전용(P7) |
| 빈 책상 더블 탭 | 빠른 작성 입력창 열기. 저장한 조각은 맨 위에 얹힌다 |

캔버스 위에 얹는 표준 컴포넌트 UI는 세 가지다: 좌상단 `←`(S-01로), 우상단 필터 버튼(태그·유형 선택 시트)과 뷰 전환 버튼(S-04로), 우하단 `+` 버튼(빠른 작성).

상태: 아이템 0개면 빈 노트 위에 "첫 조각을 끼워 보세요" 손글씨 안내. 로딩 중에는 표지 이미지를 확대한 정적 화면 + 진행 표시. Skia 로딩 실패 시 S-04로 대체하고 토스트로 알린다.

### S-04 순서 보기(리스트)

S-03과 같은 노트의 아이템을 최신순 목록으로 보여준다. 행 모양은 S-01 메모 목록과 같은 컴포넌트를 쓴다. 헤더에 노트 이름, 필터 버튼, 콜라주로 돌아가는 전환 버튼을 둔다. 필터 선택은 S-03과 공유한다.

### S-05 노트 생성·편집

하단 시트 형태다. 필드: 이름(필수, 40자), 시기·테마 설명(선택, 80자), 표지(기본 표지 8종 중 선택 또는 이미지 업로드), 테마(P6부터). 편집 모드에는 노트 삭제 버튼이 있고, 삭제 시 확인을 받는다.

### S-06 설정

항목: 계정(로그인 상태, 로그아웃), 동기화 상태(마지막 동기화 시각, 지금 동기화), 기본 테마 선택(P6), 소리 켜기/끄기, 움직임 줄이기, 데이터 내보내기(JSON + 미디어 ZIP).

### S-07 로그인

로그인 없이도 로컬 저장으로 앱 전체를 쓸 수 있다. 로그인은 동기화를 켤 때만 요구한다(A-04). 로그인 수단은 Q-03.

### 화면 전환

| 출발 | 입력 | 도착 | 전환 연출 |
| --- | --- | --- | --- |
| S-01 | 표지 탭 | S-03 | 표지가 커지며 책이 펼쳐짐(400ms) |
| S-01 | 메모 행 탭, 빠른 작성 확장 | S-02 | 아래에서 종이가 올라옴 |
| S-01 | `+` | S-05 | 하단 시트 |
| S-01 | `⋮` | S-06 | 기본 푸시 |
| S-03 | 조각 탭 | S-02 | 조각이 커지며 페이지가 됨 |
| S-03 | 뷰 전환 | S-04 | 크로스페이드 |
| S-04 | 행 탭 | S-02 | 기본 푸시 |
| S-02 | `←` | 직전 화면 | 역방향 |
| S-06 | 동기화 켜기(비로그인) | S-07 | 기본 푸시 |

"움직임 줄이기"가 켜져 있으면 모든 전환을 150ms 페이드로 바꾼다.

### 4.3 썸네일(조각 얼굴) 생성 (THM)

유형별로 위에서부터 시도하고 성공하면 멈춘다. 사용자가 지정한 이미지가 항상 최우선이다.

| 유형 | 1순위 | 2순위 | 최종 폴백 |
| --- | --- | --- | --- |
| `link` | 서버가 수집한 `og:image` | oEmbed 또는 정해진 썸네일 URL(유튜브 등) | 절차적 생성(도메인 텍스트 + 종이 질감) |
| `video` 파일 | 프레임 추출(`expo-video-thumbnails`, 웹은 `video` + `canvas`) | 사용자가 지정한 시점 스냅샷 | 절차적 생성 |
| `music` | 파일 내장 커버(ID3) 또는 스트리밍 링크 oEmbed 커버 | 파형 이미지 | 절차적 생성 |
| `image` | 원본 축소본 | — | — |
| `text` | 절차적 생성(글자 일부 + 종이 질감·색) | — | — |

| ID | 요구사항 | 수용 기준 | 단계 |
| --- | --- | --- | --- |
| FR-THM-01 | 모든 아이템은 저장 직후부터 썸네일을 갖는다. | 저장 즉시 절차적 썸네일을 표시하고, 상위 순위 썸네일이 준비되면 교체한다. 썸네일이 빈 조각은 어떤 상태에서도 보이지 않는다. | P2 |
| FR-THM-02 | 절차적 썸네일은 결정적이다. | 같은 내용 해시는 어느 기기에서나 같은 색·패턴을 만든다. 네트워크 없이 50ms 안에 생성한다. | P2 |
| FR-THM-03 | 썸네일 출처를 기록한다. | `thumbnailSource`에 `user` / `og` / `oembed` / `frame` / `cover` / `waveform` / `resize` / `procedural` / `generated` 중 하나를 저장한다. | P2 |
| FR-THM-04 | 저장하는 썸네일은 스킨이 없는 깨끗한 원본이다. | 저장 파일에 프레임·찢긴 테두리·종이 질감이 없다. 긴 변 512px WebP로 저장한다(A-11). 테마를 바꾸면 같은 썸네일이 새 스킨으로 보인다. | P2 |
| FR-THM-05 | 링크 썸네일은 서버가 수집한다. | 클라이언트는 외부 사이트를 직접 요청하지 않는다. 수집 실패·시간 초과(5초) 시 절차적 썸네일을 유지한다. | P3 |
| FR-THM-06 | 사용자가 썸네일을 직접 지정한다. | S-02 `⋮` → "썸네일 바꾸기"로 이미지를 고르면 `thumbnailSource=user`가 되고 자동 갱신이 덮어쓰지 않는다. | P4 |
| FR-THM-07 | 영상의 스냅샷 시점을 고른다. | 재생 위치를 고르고 "이 장면을 얼굴로"를 누르면 그 프레임이 썸네일이 된다. | P8 |
| FR-THM-08 | 생성형 이미지는 사용자가 요청할 때만 서버를 거쳐 만든다. | 클라이언트 번들에 API 키가 없다. 자동 호출 경로가 없다. | P8 |

### 4.6 콜라주 (COL)

## 5. 콜라주 알고리즘 명세

기획안은 규칙의 방향만 정했으므로, 아래 수치는 모두 제안 기본값이다(A-09). 전부 `collageConfig` 상수 파일 한 곳에 두고, 알고리즘은 시드를 받는 순수 함수로 구현해 단위 테스트한다.

### 5.1 밀도와 초기 배치

```
s = clamp(min(W, H) * 0.22, 96, 220)        // 기준 조각 한 변(px), W·H = 캔버스 크기
N = clamp(floor(W * H * 0.35 / (s * s)), 8, 15)   // 목표 조각 수
표시 개수 = min(N, 노트의 아이템 수)
```

예: 390×844 화면은 12개, 768×1024는 9개, 1440×900은 11개다.

| 항목 | 값 |
| --- | --- |
| 위치 분포 | 70%는 양면 페이지 안, 30%는 노트 경계에 중심을 두어 책상에 반즘 걸침 |
| 회전 | −12° \~ +12° 균등 분포 |
| 크기 배율 | 0.85 \~ 1.15 |
| 좌표 저장 | 노트 중심 기준 정규화 좌표(노트 폭 = 1). 화면 크기가 달라도 같은 상대 위치로 복원 |
| 가려짐 제한 | 어떤 조각도 면적의 70% 넘게 가려지지 않게 배치를 최대 10회 재시도 |

### 5.2 가중치 랜덤 선택

책갈피 속 아이템 중에서 노출할 조각을 고를 때 쓴다. 비복원 가중치 추출이다.

```
ageDays   = (now - createdAt) / 1일
idleDays  = lastSeenAt 있으면 (now - lastSeenAt) / 1일, 없으면 ageDays

recency   = 1 + 2 * exp(-ageDays / 7)        // 최근 저장할수록 최대 3배
staleness = 1 + min(idleDays / 30, 2)        // 오래 안 볼수록 최대 3배
fatigue   = 1 / (1 + 0.3 * seenCount)        // 자주 볼수록 감소

weight    = recency * staleness * fatigue
```

- 레이어 순서: 선택된 조각을 `recency + random(0, 1)` 오름차순으로 쌓는다. 최근 조각이 위에 올 확률이 높다.
- 시드: `hash(bookId + 연월일)`. 같은 날 같은 노트는 같은 결과를 낸다.
- `seenCount` 갱신: 조각을 탭해 에디터를 열면 +1. 노출된 채로 노트를 닫으면 세션당 +1. 두 경우 모두 `lastSeenAt = now`.

### 5.3 자연 순환

노트를 열 때 한 번 계산한다. 같은 날 다시 열면 계산하지 않는다(`CollageState.lastCycleAt`).

| 조건(`placementIdle` = now − `touchedAt`) | 동작 |
| --- | --- |
| 3일 미만 | 변화 없음 |
| 3일 이상 | 가라앉기: 레이어 순위를 하루에 한 칸씩 아래로, 위치를 가장 가까운 가장자리 쪽으로 하루에 노트 폭의 2%씩(누적 최대 15%) |
| 7일 이상 | 교체 후보: 후보 중 오래된 순으로 최대 `ceil(N * 0.3)`개를 책갈피 속으로 보내고, 같은 수를 5.2로 뽑아 빈자리 근처에 놓는다 |

- `touchedAt`은 조각을 놓았을 때, 끌었을 때, 탭했을 때 갱신한다.
- 책갈피 속에 아이템이 없으면 교체하지 않고 가라앉기만 적용한다.
- 새로 저장된 아이템은 순환과 무관하게 다음에 열 때 반드시 최상위에 놓는다(FR-COL-08).

### 5.4 쏟아내기

| 항목 | 값 |
| --- | --- |
| 꺼내는 수 | 책갈피 속이 2개 이상이면 1 또는 2(반반), 1개면 1 |
| 꺼낼 조각 | 5.2 가중치로 선택 |
| 들어갈 조각 | 표시 개수가 N을 넘는 만큼, `placementIdle`이 가장 큰 조각부터 |
| 등장 연출 | 책 접힘선의 임의 지점에서 바깥 방향 속도를 주어 600ms 동안 미끄러져 나옴 |
| 퇴장 연출 | 접힘선 쪽으로 400ms 동안 미끄러져 들어가며 페이드 |
| 재사용 대기 | 800ms |
| 모바일 흔들기 감지 | 가속도 1.8g 이상 2회 / 500ms |

### 5.5 침입자

| 항목 | 값 |
| --- | --- |
| 첫 등장 | 필터를 켠 뒤 20초 |
| 이후 간격 | 45\~90초 균등 랜덤. 드래그 중이거나 에디터가 열려 있으면 타이머 정지 |
| 후보 | 현재 필터에 맞지 않는 아이템. 80% 확률로 같은 노트, 20% 확률로 다른 노트 |
| 선택 가중치 | `staleness * fatigue` (5.2에서 `recency` 제외) |
| 동시 개수 | 1개. 새 침입자가 오면 이전 침입자는 나간다 |
| 등장 | 화면 밖 임의의 변에서 800ms 동안 미끄러져 들어와 책상 가장자리에 멈춤 |

| 저장 | 침입자 위치는 `CollageState`에 저장하지 않는다 |

## 6. 데이터 모델

핵심 엔티티는 `Item`, `Book`, `CollageState` 세 가지이고 `Attachment`와 `Theme`이 이를 보조한다. 로컬(SQLite)과 서버(PostgreSQL)가 같은 필드 이름을 쓴다.

### 6.1 공통 규칙

- `id`: 클라이언트가 만드는 UUID v7 문자열. 오프라인에서 만들어도 충돌하지 않는다.
- 시각: UTC epoch 밀리초 정수.
- 모든 엔티티에 `createdAt`, `updatedAt`, `deletedAt`(null 가능)을 둔다. 아래 표에서는 생략한다.
- 서버 테이블에는 `userId`가 추가된다.
- 파일 참조는 `localUri`(기기 안 경로)와 `remoteKey`(오브젝트 스토리지 키) 두 필드로 나눈다. 둘 중 하나만 있어도 된다.

## 7. 서버 API 계약

서버는 브라우저가 못 하는 세 가지만 맡는다: 외부 링크 메타데이터 수집, API 키 보호용 프록시, 계정 간 동기화. 모든 경로는 `/v1` 아래 JSON이고, 인증은 `Authorization: Bearer <JWT>`다.

| 메서드·경로 | 인증 | 요청 | 응답 | 단계 |
| --- | --- | --- | --- | --- |
| `GET /v1/link-preview?url=` | 선택 | URL | `{url, type, title, description, siteName, imageUrl}` | P3 |
| `POST /v1/auth/login` | 없음 | Q-03에 따름 | `{accessToken, refreshToken, user}` | P3 |
| `POST /v1/auth/refresh` | 없음 | `{refreshToken}` | `{accessToken, refreshToken}` | P3 |
| `POST /v1/auth/logout` | 필수 | — | 204 | P3 |
| `POST /v1/sync/push` | 필수 | `{books[], items[], attachments[], collageStates[]}` (변경된 행 전체) | `{applied[], conflicts[]}`. `conflicts`에는 서버 쪽 최신 행을 담는다 | P3 |
| `GET /v1/sync/pull?cursor=` | 필수 | 커서(없으면 전체) | `{books[], items[], attachments[], collageStates[], nextCursor, hasMore}` | P3 |
| `POST /v1/uploads/presign` | 필수 | `{purpose, mimeType, bytes}`. `purpose`는 `attachment` / `thumbnail` / `cover` | `{uploadUrl, remoteKey, expiresAt}` | P3 |
| `GET /v1/files/{remoteKey}` | 필수 | — | 서명된 다운로드 URL로 302 | P3 |
| `POST /v1/generate/image` | 필수 | `{purpose, prompt, itemId?, bookId?}` | `{remoteKey}` | P8 |
| `GET /v1/themes` | 선택 | — | `[{id, name, version, manifestUrl, bundleUrl}]` | P8 |

### 동작 규칙

- **링크 미리보기**: `og:image`, `og:title`, `og:description`, `og:site_name`을 읽고, 알려진 도메인은 oEmbed를 먼저 시도한다. 시간 제한 5초, 본문 2MB까지만 읽는다. 결과는 URL 기준 24시간 캐시한다. 실패하면 `{url, type, title: null, imageUrl: null}`을 200으로 돌려주고 클라이언트는 절차적 썸네일을 유지한다.
- **링크 미리보기 보안**: `http`/`https`만 허용한다. 사설·루프백·링크로컬 IP로 해석되는 주소와 리다이렉트를 차단한다. 비로그인 요청은 IP당 분당 10회, 로그인 요청은 사용자당 분당 30회로 제한한다(A-15).
- **동기화 병합**: 행마다 `updatedAt`이 더 큰 쪽을 채택한다. `collageStates`는 `placements`를 `itemId` 단위로 병합하고 placement의 `updatedAt`으로 비교한다. 삭제는 `deletedAt`이 있는 행으로 전달한다.
- **커서**: 서버가 행을 받을 때마다 단조 증가 시퀀스를 붙이고, 커서는 그 시퀀스다. 기기 시계에 의존하지 않는다. 한 번에 500행까지 돌려준다.
- **업로드**: 사전 서명 URL의 유효 시간은 10분이다. `mimeType`과 `bytes`를 FR-CLS-01, FR-CAP-07 기준으로 서버에서 다시 검증한다. `remoteKey`는 `users/{userId}/…` 형태이고 다른 사용자의 키는 403이다.
- **오류 형식**: `{"error": {"code": "string", "message": "string"}}`. 코드는 `unauthorized`, `forbidden`, `not_found`, `validation_failed`, `rate_limited`, `payload_too_large`, `internal`.
- **생성형 이미지**: 제공사 API 키는 서버 환경 변수에만 둔다. 사용자당 일일 호출 상한을 둔다(Q-06).

## 11. AI 투입 프롬프트 템플릿

이 문서를 Markdown으로 내보내 `/docs/requirements.md`로 두고, 패키마다 아래 세 프롬프트를 순서대로 쓴다. `{WP}` 자리에 `WP-1` 같은 패키지 ID를 넣는다.

### 1단계: 상세 명세 작성

```
첨부한 requirements.md는 이 프로젝트의 유일한 요구사항 기준이다. 0장의 규칙을 따라라.

{WP}의 상세 기술 명세를 /docs/specs/{WP}.md로 작성하라. 코드는 아직 작성하지 않는다.

명세에 포함할 것:
1. 이 패키지가 다루는 요구사항 ID 목록과, 각 ID를 어떤 모듈·파일이 구현하는지의 대응표
2. 파일·디렉터리 구조 (8장의 저장소 구조를 따를 것)
3. 모듈별 공개 인터페이스 (TypeScript 또는 Kotlin 타입 시그니처)
4. 화면별 컴포넌트 트리와 상태 (3장의 요소·상태·전환을 모두 반영)
5. 데이터 스키마와 마이그레이션 (6장의 필드 이름을 그대로 사용)
6. 수용 기준을 검증하는 테스트 목록 (요구사항 ID별 1개 이상)
7. 이 패키지에서 쓰는 가정(A-nn)과 걸려 있는 미결정(Q-nn) 목록
8. 이후 패키지를 막지 않기 위해 열어 둔 확장 지점

요구사항에 없는 기능을 추가하지 말고, 요구사항끼리 모순되거나 빠진 부분을 발견하면 명세 맨 앞에 "확인 필요" 목록으로 적어라.
```

### 2단계: 구현

```
requirements.md와 /docs/specs/{WP}.md를 기준으로 {WP}를 구현하라.

규칙:
- 명세의 파일 구조와 인터페이스를 따른다. 바꿔야 하면 명세를 먼저 고치고 이유를 적는다.
- 공용 코드에 웹 전용 API를 쓰지 않는다. 플랫폼 분기는 /src/platform의 *.web.ts / *.native.ts에만 둔다.
- 수치는 코드에 흩뿌리지 말고 설정 상수 파일에 모은다. 5장의 값은 collageConfig에 둔다.
- 현재 패키지보다 뒤 단계의 요구사항은 구현하지 않는다.
- 테스트 이름과 관련 코드 주석에 요구사항 ID를 적는다.
- 명세의 테스트 목록을 모두 작성하고 통과시킨다.

끝나면 다음을 보고하라: 구현한 요구사항 ID와 각 수용 기준의 충족 여부, 실행 방법, 임시 기본값으로 처리한 Q-nn, 완료하지 못한 항목과 이유.
```

### 3단계: 검증

```
requirements.md 9장에서 {WP}의 완료 기준과 포함 요구사항의 수용 기준을 하나씩 점검하라.
코드를 읽고 테스트를 실행한 뒤 표로 보고하라: 요구사항 ID | 충족/미충족 | 근거(파일·테스트 이름) | 미충족 시 필요한 수정.
요구사항에 없는데 추가된 기능과, 공용 코드에 들어간 플랫폼 전용 코드도 찾아 적어라. 직접 고치지 말고 보고만 하라.
```

WP-1은 감성 확인이 목적이므로 3단계 대신 직접 만져 보고 Q-05를 확정한 뒤 10장을 고친다.
